# 双百项目智驾域控数据采集、上传处理链路及 OTA 功能指标清单

> 文档版本：V2.0  
> 编制日期：2026-08-10  
> 适用车型：N3 类纯电充电重卡  
> 适用范围：`aura/src/data_loop/snapshot_recorder`、`zeron-upload-hub`、智驾域控 OTA 平台及 `aura-ota-agent`  
> 文档用途：功能评审、首发准入、实车联调和下线功能验收清单冻结  
> 本版范围：只列功能性指标，不设置吞吐、时延、并发、容量、成功率等性能门限

## 1. 编号和状态说明

### 1.1 编号规则

| 标识 | 含义 |
|---|---|
| `SB-DATA-F-xxx` | 双百项目数据采集、车端上传及云端处理链路功能项 |
| `SB-DCOTA-F-xxx` | 双百项目智驾域控 OTA 功能项 |
| `STD-L2` | 需要与 L2 适用标准建立追溯的项目内部标签 |
| `STD-L4` | 需要与 L4 适用标准建立追溯的项目内部标签 |
| `STD-DATA` | 需要与汽车数据处理、记录要求建立追溯的项目内部标签 |
| `STD-SEC` | 需要与汽车信息安全要求建立追溯的项目内部标签 |
| `STD-OTA` | 需要与汽车软件升级要求建立追溯的项目内部标签 |

`SB-*` 和 `STD-*` 均为项目内部分类或检查编号，不是国家标准号、国家标准条款号或认证编号。标签项验收通过，不代表已经完成国家标准符合性认证。

### 1.2 当前状态

| 状态 | 判定口径 |
|---|---|
| 已具备 | 代码中已存在对应功能，仍需完成配置核查和实车/端云验收 |
| 部分具备 | 已有主体代码，但存在配置、接口契约、安全门禁或闭环缺口 |
| 当前缺失 | 当前代码中未找到满足量产要求的实现证据 |
| 待实车验证 | 代码路径存在，但结论依赖量产域控、网络、存储或启动链验证 |

### 1.3 上线阶段

- **首次上线必须**：正式首发前必须通过；不得以“后续 OTA 完善”替代身份、完整性、传输安全、验签、升级门禁、健康检查、回滚和审计。
- **后续完善**：首发已有人工控制、基础监控和回退措施后，可通过 OTA 或平台迭代增强。

## 2. 标准对齐边界

本清单按以下标准方向建立功能追溯入口：

- GB/T 40429-2021《汽车驾驶自动化分级》
- GB/T 44464-2024《汽车数据通用要求》
- GB 44497-2024《智能网联汽车 自动驾驶数据记录系统》
- GB 44495-2024《汽车整车信息安全技术要求》
- GB 44496-2024《汽车软件升级通用技术要求》
- GB/T 41871-2022《信息安全技术 汽车数据处理安全要求》

本清单只检查智驾域控相关功能是否存在、能否形成闭环及是否具备验收证据。正式验收前仍须冻结适用条款、数据字典、Topic 清单、schema、接口版本和测试用例，并另建受控标准条款追溯矩阵。

## Part A：智驾域控数据采集、车端上传及云端处理链路

### A1. 当前链路边界

```text
规则/云端命令
    ↓
snapshot_recorder 规则合并、条件判断、事件触发和 MCAP 录制
    ↓
本地持久化上传队列
    ↓
zeron-upload-hub 预登记任务
    ↓
车端加密并上传对象存储
    ↓
zeron-upload-hub 更新上传状态、记录处理状态和流水线步骤
    ↓
Argo Events / 下游处理流程
```

`zeron-upload-hub` 属于本 Part 的云端任务和处理能力。车端文件上传完成、Hub 状态登记完成和下游处理完成是三个不同的功能终态，不得互相替代。

## 3. 首次上线阻断项

以下项目当前不能直接判定为首发通过，必须在正式验收前关闭：

| 阻断项 | 当前问题 | 关闭标准 |
|---|---|---|
| 数据规则持久化 | 无最后有效规则持久化证据 | 断电和断网后仍可使用经批准的最后有效规则，并可追溯版本 |
| L2/L4 数据字典 | Topic、字段、schema 和质量位未冻结 | 建立受控数据字典、schema、版本和逐字段测试用例 |
| 对象完整性 | 无车端与云端 SHA256 对账 | 对象大小和 SHA256 一致后才允许进入上传成功终态 |
| 数据 TLS | `verify_ssl: false` | 生产严格校验证书，错误证书和明文连接失败关闭 |
| Hub 下游闭环 | `VENDOR_DELIVERED` 与仅接受 `UPLOADED` 的 DAG 入口不一致 | 冻结唯一状态契约，并完成一次真实上传到处理完成的自动闭环 |
| 存储凭证 | Hub 返回静态模拟密钥 | 改为短期、最小权限且按车辆/任务隔离的凭证 |
| 量产 API | 新旧任务流程并存 | 冻结唯一量产接口、状态机、错误码和兼容策略 |
| 数据治理 | 数据最小必要、权限、保留和删除闭环证据不足 | 完成数据分类、授权、审计、保留和删除功能验收 |
| OTA 验签 | Cosign 可因未配置而跳过 | 生产公钥和工具必须存在，任何验签异常均拒绝升级 |
| OTA Pre-flight | 配置为空或检查异常时存在跳过路径 | 首发检查项全部配置，缺失和异常失败关闭 |
| OTA 健康检查 | 默认关键 Topic 和服务清单为空 | 冻结智驾关键健康检查集并完成故障注入 |
| OTA 传输安全 | 当前默认使用 HTTP | 生产启用 HTTPS/mTLS 和设备级身份 |
| OTA 防重放/降级 | 缺少完整门禁证据 | 旧 Action、过期任务和未授权降级均被拒绝 |
| OTA 断电恢复 | 缺少量产域控实机结论 | 首发实际升级路径完成分阶段断电/重启恢复测试 |

## 5. 现场使用规则

1. 两个 Part 使用同一判定口径：功能正常链路完成、异常进入明确状态、关键安全功能失败关闭，并具备可复核证据。
2. “已具备”只表示代码中存在功能，不等于车辆已经验收通过；现场仍须填写“现场结论”。
3. 现场结论统一填写：`通过`、`不通过`、`不适用`。`不适用`必须填写批准理由。
4. 首次上线必须项只要有一项不通过，智驾域控数据链路或 OTA 对应 Part 不得判定通过。
5. 本清单可以作为双百项目智驾域控功能验收基线，但不能替代整车其他系统验收、性能验收或正式国家标准符合性认证。
