> 文档版本：V1.0
> 编制日期：2026-08-10
> 文档状态：工程指标基线草案，适用于项目评审、测试设计、首发准入和下线验收标准冻结
> 适用车型：N3 纯电可充电重卡
> 适用对象：智能驾驶域控数据采集与上传链路、智能驾驶域控 OTA、独立 FDC 双 5G 模块 MQTT 固件 OTA
> 参考资料：`shuangbai-project-acceptance-checklist.md`、`shuangbai-project-eol-checklist-feishu.md`、`specs.md`

> **编号声明：** `FPI-DATA-*`、`FPI-DCOTA-*`、`FPI-FDCOTA-*` 均为双百项目内部“功能性能指标”编号，不是国家标准号、国家标准条款号或认证编号。正式国标条款仍须在受控标准追溯矩阵中映射。

## 1. 使用边界

1. 本清单只关注智驾域控数采/上传、智驾域控 OTA，以及独立 FDC 的 RTK/IMU 接口和 MQTT 固件 OTA。
2. FDC 是智驾域控之外的独立双 5G 模块。FDC OTA 结论不得替代智驾域控 OTA 结论，智驾域控 OTA 结论也不得替代 FDC OTA 结论。
3. 本清单不验收动力电池、VCU、BMS、高压、充电系统、转向、制动执行器、FDC 射频及 FDC 内部定位算法本体；只验收这些对象与智驾域控相关的接口、状态、门禁和失效处置。
4. L2 数采需覆盖功能状态、驾驶员/HMI、控制权、传感器质量、时间基准、事件记录和故障追溯。L4 还需覆盖 ODD、ADS 状态机、最小风险状态、感知到控制证据链和远程协助状态。
5. 表中标为“工程候选”的数值来自当前项目设计，不是国家统一阈值。正式量产前必须写入受控阈值档案，并由研发、测试、安全、质量和项目负责人批准。

## 2. 统一判定规则

| 项目 | 统一规则 |
|---|---|
| 首次上线 | 所有适用 P0、P1 必须达到首次上线验收标准；不得以“后续 OTA 再补”替代身份、完整性、签名验签、回滚、门禁、审计和故障可发现性 |
| 后续完善 | 只允许完善自动化、性能、运维、看板和诊断范围，不得降低首次上线安全边界 |
| 功能通过 | 正常链路完整，异常进入明确状态，无越权、静默丢失、错误归车、伪成功或不可恢复状态 |
| 性能通过 | 在批准的车型、文件、网络、并发、负载和观察窗口下达到冻结目标，并保留 P50/P95/P99、失败率和资源曲线 |
| 连续量判定 | 时间同步、RTK/IMU、频率、时延和吞吐等连续量须使用批准的测量方法、测量能力和保护带 |
| 失效即失败 | 输入缺失、解析失败、checker 异常、超时、服务不可达或结果不确定时判定失败，不得默认通过 |
| 证据要求 | 至少包含 VIN、deviceId、硬件变体、软件/固件版本、时间、测试条件、原始日志或抓包、实测值和结论 |
| 状态枚举 | `未验证`、`通过`、`不通过`、`不适用`；不适用须填写批准编号和理由 |

基线性质统一使用：

- `功能基线`：首次上线必须具备的确定性功能要求。
- `工程候选`：已有设计目标，但正式验收前仍须冻结测试条件和批准值。
- `IF/SAF 待冻结`：必须由接口规范、供应商规格或安全案例给出项目值。
- `OPS 待冻结`：必须由项目规模、车队运营和 SLA/SLO 给出项目值。

## 3. 首次上线必须具备的最小集合

首次上线不得缺少以下能力：

1. 数据链路：事件触发、录制、元数据、队列持久化、任务创建、对象上传、SHA256 对账、状态闭环和云端确认。
2. 数据边界：L2/L4 责任字段、FDC RTK/IMU、新能源状态、时间同步、数据最小必要和生产身份。
3. 数据可靠性：断网不丢、失败隔离、磁盘保护、资源隔离、TLS、schema 兼容和全链路追溯。
4. 域控 OTA：唯一设备、签名验签、兼容矩阵、Pre-flight、默认充电中拒绝、断点续传、断电恢复、健康检查、自动回滚、版本对账和审计。
5. FDC OTA：独立身份、双 5G 资产绑定、MQTT/TLS/ACL、accepted/rejected、会话和 retained 清理、RTK/IMU 兼容、双卡切换、断电恢复、回滚、启动真实性和不可变审计。
6. 下线 readiness：数据上传、域控 OTA、FDC OTA 三条链路分别达到确定终态，取得可信报告和云端确认。
