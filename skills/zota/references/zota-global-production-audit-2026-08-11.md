> 验证状态：本轮未运行代码、测试、构建或服务；所有整改项均为**未复验**

## 1. 审计目的和范围

本报告用于检查当前 ZOTA 相关实现是否具备双百项目新能源充电重卡智驾域控数采与 OTA 的生产上线基础。报告是对当前代码现状的风险审计，不替代功能指标清单、正式测试报告、国家标准符合性认证或整车放行结论。

### 1.1 纳入范围

| Part | 审计对象 | 链路边界 |
|---|---|---|
| Part A：智驾域控数据采集与上传 | `aura/src/data_loop/snapshot_recorder`、`zeron-upload-hub` | `snapshot_recorder -> 本地上传队列 -> zeron-upload-hub -> 对象存储 -> 处理 DAG/回调` |
| Part B：智驾域控 OTA | `zota-repo`、`zota-repo-web`、HawkBit/ZOTA 配置、`aura-ota-agent` | `制品/版本管理 -> 发布/审批 -> Rollout/DDI -> 域控下载、验签、安装、健康检查、回滚和反馈` |
| 公共基础面 | 认证、凭据、存储、数据库、Kubernetes、审计和 Web 管理面 | 仅检查直接影响上述两条生产链路的实现 |

### 1.2 不纳入范围

- FDC 双 5G、RTK、IMU 及 FDC MQTT 固件升级；
- 产线电检、EOL 工位和整车其他域控制器；
- 智驾算法功能、整车制动/转向性能和道路功能安全测试；
- 性能压测、实车断电测试、网络故障注入和正式国家标准认证。

### 1.3 与现有文档的关系

以下文档保持不变：

- `shuangbai-project-data-ota-functional-indicators.md`：目标功能指标；
- `shuangbai-project-acceptance-checklist.md`：工程准入与验证要求；
- `shuangbai-project-eol-checklist-feishu.md`：逐车下线执行模板。

本报告回答的是“当前实现是否已达到可上线状态”。现有清单中标记为“已具备”或“部分具备”的能力，仍可能因安全门禁、数据完整性、失败关闭、持久化或状态闭环问题而被本报告判定为上线阻断。

## 2. 审计口径

### 2.1 严重级别

| 级别 | 判定口径 |
|---|---|
| Critical | 可导致未授权控制、凭据泄露、数据不可恢复丢失、未验签升级或绕过发布审批；必须在任何生产上线前关闭 |
| High | 可导致错误数据、重复或丢失任务、不完整发布、不可回滚、服务或存储不一致；实际启用路径上线前必须关闭 |
| Medium | 生产加固、审计、可维护性或部署一致性不足；应在首发前关闭，或形成有责任人、期限和补偿措施的批准偏离 |
| Low | 不直接改变当前安全结论的工程质量问题；应进入常规整改计划 |

### 2.2 证据和判定规则

1. 代码证据采用“仓库相对路径 + 行号”记录。
2. 涉及凭据的证据只列文件和行号，不展示秘密原文。
3. 静态审计只能证明代码中存在风险路径，不能证明整改后已通过。
4. 未执行的动态验证统一标记为“未复验”，不得填写“通过”。
5. Critical 未全部关闭时，数采和 OTA 均不得生产上线。

| 合计 | 30 | **当前不具备生产上线条件** |

直接阻断上线的核心原因：

1. 仓库和配置中存在真实凭据，必须先吊销、轮换和清理；
2. Upload Hub 无认证，车辆、任务、状态、回调、管理和存储凭据接口可匿名访问；
3. 数采生产配置关闭 TLS 证书校验，车辆身份可通过 Header 伪造；
4. 数采失败隔离会删除原始 MCAP 和事件目录，存在不可恢复的数据丢失；
5. OTA Agent 在公钥或验签工具缺失时允许跳过验签；
6. OTA 发布接口未强制绑定审批，operator 可直接创建并启动 forced rollout。
