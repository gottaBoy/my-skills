> 适用对象：智驾域控数采/上传、智驾域控 OTA readiness、独立 FDC 双 5G 模块 RTK/IMU 接口及 MQTT OTA readiness

> **量产执行警告：飞书粘贴版不等于受控发布版。** 只要任一适用检查项仍标有“待新增”“待修正”“需确认”“待填写”，或对应阈值、适用性、ZEOL 映射、checker、工位有效性、人员授权门禁及 MES 互锁尚未冻结并验证，就不得凭本表勾选放行。正式量产版必须关闭这些状态，或采用经质量、测试、安全和项目负责人批准的受控人工/脚本替代方案，将原始证据写入同一 `EOL-REPORT-ID`，完成工艺编号、生效日期及编制/审核/批准后方可执行。

> **用途边界：** 本文件是每辆车执行的短表，不替代 `QL-1` 设计/法规准入、`QL-2` 变体/版本准入、`QL-4` 首件/批次抽检和 `QL-5` OTA 发布监控。FDC 是智驾域控之外的独立双 5G、RTK/IMU 模块；本表只验收域控与 FDC 的 RTK/IMU/网络接口边界，以及 FDC MQTT OTA readiness，不把 FDC 内部定位、惯导、射频或整机性能计入智驾域控通过结论。FDC 自身的北斗/RTK 定位模块仍须由法规、质量和供应商负责人判定 `GB 48063-2026` 适用性并在上层形成证据；每车只核对当前模块身份/变体被有效报告覆盖。表内不直接复制工程候选阈值，正式判定统一引用主清单第 3.1 节已批准的 `EOL 阈值档案版本`；候选值不能冒充国家标准统一数值或正式验收门槛。

> **V2.10 变更摘要：** 同步主清单 V2.18：逐车增加 FDC 整体及可独立识别子固件/配置清单对账、GNSS/RTK 天线相位中心/杆臂/双天线基线和 IMU 安装外参哈希对账、MQTT Topic/QoS/认证/retained/会话/消息过期契约版本及无旧任务检查。完整动态标定、retained/会话/过期消息负向测试和模块性能仍由 `QL-2/QL-4` 覆盖，不下沉为每车重复试验。当前仍为 `S1 整改`，不可直接量产放行。

### 飞书粘贴步骤

1. 在 Markdown 预览中按章节复制已渲染的表格，不要一次性粘贴整份原始 Markdown 源码。
2. 粘贴到飞书文档，保留章节标题、表头、检查编号、来源、优先级和状态列。
3. 核对每张表的表头列数，检查各 EOL 前缀的首尾编号和连续性，确认没有缺行、错列或合并单元格错位。
4. 将状态列限制为 `未执行/通过/不通过/不适用` 枚举，锁定表头和编号列；P0/P1 不允许现场录入“有条件通过”。
5. 转换为正式受控模板时，填写受控文件/工艺编号、生效日期、编制/审核/批准、适用车型/版本、受控标准清单版本、标准状态核查日期和阈值档案版本，并通过正负样件验证后发布。

## 2. 统一判定规则

| 项目 | 规则 |
|---|---|
| 状态 | 仅使用 `未执行`、`通过`、`不通过`、`不适用`；逐车 P0/P1 不使用“有条件通过”代替关闭 |
| P0 | 任一适用 P0 不通过，立即隔离车辆，禁止下线 |
| P1 | 所有适用 P1 必须通过；如确需偏离，须在本车执行前由上层准入完成影响分析、书面批准并修改适用性或受控基线，本表不得由操作员现场豁免或有条件放行 |
| 不适用 | 必须填写批准的适用性档案/豁免编号和理由，不能仅写“本车没有” |
| 实际结果 | 填实测值、版本、ID、时间、数量或错误码，不得只写“正常” |
| 证据 | 自动检查须引用 ZEOL test/result ID；人工检查须附照片、日志、截图、抓包或审批编号 |
| 上层覆盖 | 单车配置必须被有效 `QL-1/QL-2/QL-4` 报告覆盖；单车表不能补救上层报告缺失 |
| 标准有效性 | 本车引用的受控标准清单版本和标准状态核查日期必须在批准有效期内；进入 `S2/S3`、新版本准入和正式 OTA 发布前须重新查询官方标准平台及主管部门公告，发现发布、实施、修改、废止、替代或管理要求变化时先完成影响分析 |
| 完整 OTA | 每车不实际刷写域控或 FDC；成功、失败、断电、回滚、弱网和双 5G 切换由 `QL-2/QL-4` 覆盖 |
| GB 44497 | 仅在法规负责人判定车辆配置落入该标准适用范围时作为强制依据；不得因车辆为 L2 就自动判定适用 |
| GB 48063 | 由法规、质量和 FDC 供应商使用受控正式文本判定 FDC 北斗/RTK 定位模块是否适用；适用时核对型式/专项试验和变体覆盖，不适用时核对批准编号和理由。2027-02-01 前按已发布标准提前对齐，实施日起按强制性 `REG` 执行；完整模块性能试验不进入每车 EOL |
| 数据合规 | 每车只核对批准的数据 schema、精度/脱敏策略、测绘地理信息适用性结论和受控 EOL 测试数据；个人信息、重要数据、测绘活动/成果、资质和跨境适用性由 `QL-1` 负责人判定 |
| EOL 测试数据 | 冒烟 trigger 必须使用合成、静态或最小化测试数据并带 EOL 标识，不得为工位测试上传非必要真实个人信息、敏感个人信息或重要数据 |
| 失效即失败 | checker 异常、输入缺失、解析失败、超时、服务不可达或结果无法确定时判定“不通过”，不得使用默认值或人工勾选改为通过 |
| 连续量临界值 | RTK/IMU、时间同步、频率、时延、新鲜度等连续量必须引用有效的测量能力和保护带规则；实测值进入批准临界区时不得直接通过，按预定义复测/隔离规则处置，禁止反复测量后择优取值 |
| 总节拍和工位异常 | 本车 `T_eol_total` 超过批准值、依赖服务超时、工位异常、容量/排队/隔离上限触发时，车辆保持隔离并执行批准的堵线/降级/停线反应计划；不得关闭 P0/P1 checker、缩减检查范围或手工通过保产 |
| 返工 | 原失败报告不可覆盖；修复后生成新 `EOL-REPORT-ID` 并关联原报告和返工单 |
| 放行失效 | 放行结果必须绑定 VIN、报告哈希、生产配置哈希和时间；放行后软件、标定、证书、身份、配置或关键部件变化时，原放行自动撤销并按批准范围重跑 |
| 人员授权 | 执行、人工判定和复核使用唯一账号，当前资格/岗位授权有效且岗位范围匹配；操作员不得兼任最终质量放行，隔离解除和互锁恢复按批准矩阵执行双人或独立授权 |
| Required checker | 所有适用 P0/P1 required checker 必须被当前 ZEOL 识别、启用、实际执行并产生受控结果；expected/executed/result 必须逐项一致，unknown、skipped、disabled、未登记、异常退出或结果缺失均判定“不通过” |
| Pipeline 来源与 fallback | 实际执行的远程或本地 Pipeline 必须有批准编号、版本、签名/哈希、适用车型/配置和有效期；远程加载失败时只有批准白名单内的等效版本可 fallback，未批准或来源不明直接失败 |
| 生产模式 | 量产执行必须明确为 production；检测到 `--mock`、simulation、test mode、默认通过、硬编码成功或人工 bypass 时直接失败。批准的 GNSS 仿真/重辐射设备只能作为受控参考输入，不得冒充车端 checker 成功 |
| 操作员认证 | 当前认证安全基线必须有效；PIN/口令不得继续使用仅快速 SHA-256 的量产认证记录，须使用批准的带唯一 salt 的口令 KDF，并启用失败限速/锁定、会话过期、审计和受控恢复 |

来源代码统一使用：`REG` 现行法规/已实施强制 GB，`STD` 推荐性标准或提前对齐的已发布标准，`SAF` 安全案例，`IF` 受控接口/数据字典，`ENG` 工程基线，`OPS` 运营基线，`SUP` 供应商规格，`QL` 上层准入报告，`MON` 尚未发布的法规/标准动态监测项。`MON` 不得直接作为逐车通过依据。

## 8. 行业最佳实践和正式使用边界

本表是面向智驾域控数采、域控 OTA readiness 和独立 FDC MQTT OTA readiness 的稳健行业实践模板：采用 `QL-1 ~ QL-5` 分层准入，对 VIN/身份/版本/配置/关键接口/最终状态等单车特有且可无损检查的项目执行 100% EOL，对完整 OTA、断电、故障注入、容量和场景回归按变体、版本、首件或批次验证；并采用唯一身份、关键部件装配防错、正负样件、连续量测能力和保护带、完整 EOL 节拍/容量/可用率、人员能力/岗位授权/职责分离、失败隔离、不可覆盖证据、返工追溯和 MES 互锁。这些做法符合汽车软件、IATF/APQP/Control Plan、MSA 及 OTA 安全工程的通行方法，但不表示每个项目、每个频次或每个阈值都是行业统一要求。

1. 冻结主清单第 3 节和第 3.1 节全部适用项目值、阈值、容差、频次和统计口径，包括连续量测不确定度/能力/保护带、`T_eol_total`、工位容量/可用率、依赖服务超时和隔离上限；

11. GB 48063-2026 已于 2026-07-30 发布并将于 2027-02-01 实施。FDC 北斗/RTK 定位模块由法规、质量和供应商负责人使用受控正式文本判定适用性；适用时在实施前完成型式/专项试验、供应商放行、变更和生产一致性证据及变体覆盖，不适用时形成批准编号和理由。逐车只执行 `EOL-META-019` 身份/报告覆盖对账。
12. 新能源接口基线使用现行 GB 18384-2025、GB 38031-2025、GB/T 32960.1~4-2025 和 GB 44263-2024；按实车充电接口/协议冻结 GB/T 18487、GB/T 20234、GB/T 27930 的具体部分和版本。逐车表只验收域控消费的状态、门禁和失效处置，不替代整车、电池、T-Box 或充电系统验收。
13. GB 7258-2017 及第 2 号修改单、GB 12676-2014 仍是现行强制基线；其修订计划 `20250058-Q-312` 当前暂缓、`20262938-Q-339` 正在起草，仅进入 `MON/QL-1`，不得提前替代现行标准。

### 8.1 文档发布四态

| 状态 | 允许用途 | 进入下一状态的核心条件 |

### 8.2 结论速查

| 判定维度 | 结论 |
|---|---|
| Checklist 方法框架是否属于行业最佳实践 | 是。分层准入、对单车特有/无损项目执行 100% EOL、变体/版本覆盖、关键部件身份与装配防错、正负样件、连续量测能力和保护带、完整工位节拍/容量/可用率、人员培训/资格/岗位授权/职责分离、required checker fail-closed、批准 Pipeline/fallback、生产旁路禁用、失败隔离、证据不可覆盖、返工追溯、PFMEA/Control Plan/反应计划关联和 MES 互锁属于稳健的汽车行业实践 |
| 当前“验收标准”是否已是行业统一最佳标准 | 不是。判定逻辑和证据结构可作为最佳实践模板，但时间、时延、频率、误差、容量、成功率、保留期、抽检频次、过程能力目标、保护带、`T_eol_total` 和测试条件必须按正式条款、ICD、安全案例、供应商规格、客户要求或批准的工程/SLA 基线冻结 |
| 当前表是否证明项目已经按最佳实践运行 | 否。文档结构正确不等于 checker、工位、人员、证据链和 MES 互锁已经实现；必须用正负样件、量测能力、生产环境负向测试、可信报告和持续过程数据证明 |
| 勾选本表是否等于国家标准符合性 | 否。必须用受控标准全文完成条款、测试用例和证据映射，并完成适用的准入、生产一致性、OTA、道路运行和召回义务 |
| OTA 召回是否由本表单车全绿证明完成 | 否。单车表只核对当前准入/召回处置状态；召回的受影响 VIN/版本范围、触达、安装、实际运行版本、失败/离线/拒绝/不可达车辆追踪和未完成处置由 `QL-5` 统一闭环 |
| 车辆属于 N3 是否足以完成商用车适用性判定 | 否。N3 仅表示质量类别；还必须冻结货车/牵引车/专用车及挂车组合、最大允许总质量/轴型、制动/转向架构、营运/货物属性和运营场景，并由 `QL-1/QL-2` 判定专项标准、ODD 及道路/运营许可适用性，单车通过 `EOL-META-018` 对账 |
| L4 标准如何判定 | 截至 2026-08-10，GB/T 44721-2024 是当前实施中的推荐性通用要求；GB 44721-2026 已于 2026-07-30 发布，将于 2027-07-01 实施并全部代替前者。过渡期执行双基线，实施日起按强制基线执行 |
| FDC 北斗/RTK 定位模块如何判定 | GB 48063-2026 是已发布、尚未实施的强制性国家标准，2027-02-01 起实施。实施前由法规、质量和供应商按 `STD` 提前对齐并判定当前模块是否落入正式范围；实施日起适用模块按 `REG` 执行。每车只核对模块身份/变体及有效报告覆盖，不重复完整模块性能试验 |
