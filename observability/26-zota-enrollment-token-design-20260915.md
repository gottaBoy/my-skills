## 目标

1. 新车首次安装时不预置正式 Target 安全令牌。
2. 使用共享 enrollment token 换取 `sp_target.sec_token`。
3. Agent 持久化 target token 后，用它成功登录服务端，才完成 enrollment 确认。
4. exchange 响应丢失、agent 崩溃、重复请求等场景不能把车辆锁死。
5. 不使用 VIN 作为 secret，不把 Target attributes 当凭证存储。

## 术语

- `controllerId`：设备身份，通常可以用 VIN。
- `enrollment token`：安装期平台级共享 secret。一个 token 可以服务多台车，
  不区分 tenant。
- `target issuance`：某个 `tenant + controllerId` 的登记事实，状态为
  `PENDING` 或 `CONFIRMED`。
- `target token`：现有 `sp_target.sec_token`，后续 DDI 请求使用
  `Authorization: TargetToken <token>`。

## 核心语义

登记单位是 `tenant + controllerId`，不是全局 enrollment token。enrollment token
本身是平台级的，创建后可以被任意 tenant 下的 agent 使用；首次 exchange 会把
`tenant + controllerId` 固定到 issuance 中。

1. 同一个 enrollment token 可以被多个 VIN 使用。
2. 每个 `tenant + controllerId` 永远只有一条 issuance 记录。
3. exchange 首次为该 VIN 创建 `PENDING` issuance，并绑定当时使用的
   enrollment token ID。
4. `PENDING` 下用同一个 enrollment token 重试，必须返回同一个 target token，
   不能轮换。
5. `PENDING` 下换任何其他 enrollment token，返回 `409`。
6. 只有拿到换出的 target token 并成功认证后，confirm 才能把状态改为
   `CONFIRMED`。
7. `CONFIRMED` 后，该 VIN 不能再用任何 enrollment token exchange，包括新建的
   enrollment token。

新建 enrollment token 可以服务新 agent 安装包或新车辆，但不能解锁已
`CONFIRMED` 的 VIN。

## API

### 创建共享 enrollment token

```http
POST /rest/v1/enrollments
Content-Type: application/json
```

```json
{
  "expiresInDays": 7
}
```

服务端生成 32 字节随机 token，只在响应中返回一次明文：

```json
{
  "id": 123,
  "expiresAt": 1760985600000,
  "enrollmentToken": "zet_9fP4mVdLq2xK8aQ7sYw3RtN6bH1uC0eZ"
}
```

### 撤销 enrollment token

```http
DELETE /rest/v1/enrollments/{id}
```

撤销后不可 exchange。已换出的 target token 在 confirm 时不再依赖 enrollment
token，因此撤销不影响尚未 confirm 的合法重试。

### Exchange

```http
POST /{tenant}/enrollment/v1/{controllerId}/exchange
Authorization: EnrollmentToken <token>
```

服务端在一个事务内：

1. 校验 enrollment token hash、撤销和过期状态。
2. 查找该 `tenant + controllerId` 的 issuance。
3. 不存在则创建 `PENDING` issuance 并绑定 enrollment token ID。
4. `PENDING` 且 enrollment token ID 相同则幂等返回。
5. `PENDING` 但 enrollment token ID 不同则返回 `409`。
6. `CONFIRMED` 则返回 `409`。
7. Target 不存在则创建；若 target 已存在但 issuance 不存在，返回 `409`，
   不允许共享 enrollment token 领取已有 target 的 `sp_target.sec_token`。
8. 返回当前 target token，不轮换，不确认。

响应：

```json
{
  "targetToken": "7e8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d"
}
```

### Confirm

```http
POST /{tenant}/enrollment/v1/{controllerId}/confirm
Authorization: TargetToken <target-token>
```

服务端使用 target token 认证。认证成功且 token 等于当前
`sp_target.sec_token` 时，`PENDING` 更新为 `CONFIRMED`。第一次成功和重复成功
都返回 `204`；token 不匹配返回 `401`，状态保持 `PENDING`。

## 数据模型

```sql
CREATE TABLE sp_target_enrollment_token (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    token_hash VARCHAR(128) NOT NULL,
    expires_at BIGINT NOT NULL,
    revoked_at BIGINT,
    created_by VARCHAR(64) NOT NULL,
    created_at BIGINT NOT NULL,
    optlock_revision INT NOT NULL
);

CREATE TABLE sp_target_enrollment_issuance (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    tenant VARCHAR(40) NOT NULL,
    controller_id VARCHAR(256) NOT NULL,
    enrollment_token_id BIGINT NOT NULL,
    status VARCHAR(16) NOT NULL,
    issued_at BIGINT NOT NULL,
    confirmed_at BIGINT,
    optlock_revision INT NOT NULL
);
```

唯一键：

- `sp_target_enrollment_token(token_hash)`
- `sp_target_enrollment_issuance(tenant, controller_id)`

字段语义：

- `token_hash`：HMAC-SHA256(enrollment token, server secret)
- `expires_at`：毫秒时间戳，exchange 时校验
- `revoked_at`：非空表示管理端撤销
- `status = PENDING`：已 exchange，尚未确认
- `status = CONFIRMED`：target token 已成功登录并确认，登记永久关闭
- `enrollment_token_id`：该 VIN 首次 exchange 使用的共享 token

不存明文 enrollment token，也不复制存 target token。

已有 target 但没有 enrollment issuance 的车辆不能通过 exchange 取回旧
`sec_token`。这类重装、迁移或凭证丢失场景必须走管理端的重置流程，避免全平台
共享 enrollment token 变成已知 VIN 即可领取正式凭证的接口。

## 状态机

```text
no issuance
  |-- exchange with valid enrollment token --> PENDING

PENDING
  |-- exchange with same enrollment token  --> PENDING, same target token
  |-- exchange with other enrollment token --> 409
  |-- confirm with current target token    --> CONFIRMED
  |-- confirm with wrong target token      --> 401, remain PENDING

CONFIRMED
  |-- confirm with current target token    --> CONFIRMED
  |-- exchange with any enrollment token   --> 409

revoked / expired enrollment token
  |-- exchange --> 401
```

## Agent 启动状态机

```text
start
  |
  |-- target-token exists and valid
  |       |
  |       |-- enrollment-token exists
  |       |       |-- confirm
  |       |       |-- confirm success -> delete enrollment token
  |       |       |-- confirm fail -> keep both, start with target token
  |       |
  |       '-- no enrollment token -> start normally
  |
  '-- target-token missing
          |
          |-- enrollment-token exists
          |       |-- exchange
          |       |-- persist target token atomically
          |       |-- confirm
          |       |-- delete enrollment token only after confirm success
          |
          '-- no enrollment token -> fail fast
```

要点：

1. runtime target token 文件优先级最高。
2. exchange 失败不删除 enrollment token。
3. target token 落盘失败不 confirm。
4. confirm 失败不删除 target token。
5. 只有 confirm 成功才删除 enrollment token。
6. agent 未取得有效凭证前不进入 OTA poller。

### Agent 实现

- 配置字段：

```yaml
zota:
  enrollment_token_file: /etc/zota-agent/enrollment-token
  target_token_file: /var/lib/zota-agent/target-token
```

- 启动顺序：

1. 读取 target token 文件；存在则优先使用。
2. 若 enrollment token 文件仍存在且 target token 不存在，调用 exchange。
3. 将返回的 target token 写入同目录临时文件，`fsync` 后 `rename` 覆盖，
   文件权限 `0600`。
4. 调用 confirm；只有 HTTP 2xx 才删除 enrollment token 文件。
5. 使用 target token 创建 DDI client 并进入 poller。

`config.Validate` 允许静态 token、gateway token、bootstrap token、
enrollment token 或 target token 文件任一存在；否则启动失败。

## 崩溃恢复

| 崩溃点 | 结果 |
|---|---|
| exchange 前 | 下次继续 exchange |
| exchange 后、落盘前 | issuance 仍 `PENDING`，可重新 exchange 并拿回同一 target token |
| 落盘后、confirm 前 | 下次用 target token 补 confirm |
| confirm 后、删除 enrollment 前 | 下次发现 target token 存在，补 confirm 并清理 |

## 并发语义

1. enrollment token 和 issuance 查询都使用悲观锁。
2. `tenant + controller_id` 唯一键是并发首次 exchange 的最终防线。
3. 不同 VIN 可以并发使用同一个 enrollment token，互不消耗。
4. 同一 VIN 并发首次 exchange 时，数据库只允许一条 issuance；失败方重试后
   读取已有 issuance，并按状态机返回或拒绝。
5. `PENDING` 下重复 exchange 不轮换 target token。

## 安全要求

1. enrollment token 只在创建响应中出现一次。
2. 服务端只保存 HMAC-SHA256 hash。
3. 生产必须 HTTPS。
4. exchange 和 confirm 禁用 CORS。
5. 不把 token 写入日志、异常、审计事件或 APM。
6. exchange、confirm 按源 IP 和 token hash 限流。
7. enrollment token 过期时间由创建请求指定。
8. enrollment 重试不轮换 target token。
9. agent 文件权限 `0600`。
10. 不把 enrollment token 存入 Target attributes。

## 测试清单

服务端当前单测覆盖：

1. `PENDING` 下重复 exchange 返回同一个 target token。
2. `CONFIRMED` 后不能再次 exchange。
3. `PENDING` 下换其他 enrollment token 被拒绝。
4. 过期 enrollment token 被拒绝。
5. 撤销 enrollment token 被拒绝。
6. confirm 使用正确 target token 成功。
7. confirm 使用错误 target token 失败且保持 `PENDING`。
8. confirm 幂等。

REST 层测试覆盖：

1. exchange 缺少 enrollment token 返回 `401`。
2. exchange 成功返回 target token。
3. `PENDING` 下换其他 enrollment token 返回 `409`。
4. `CONFIRMED` 后 exchange 返回 `409`。
5. confirm 缺少 target token 返回 `401`。
6. confirm 成功返回 `204`。
7. confirm 使用错误 target token 返回 `401`。

后续补充：

1. 并发首次 exchange 的数据库集成测试。
2. 日志无 token 断言。

Agent 测试覆盖：

1. 首次 exchange、落盘、confirm 成功后删除 enrollment token。
2. confirm 失败时保留 enrollment token 和 target token。
3. 崩溃后已有 target token 时只补 confirm，不重复 exchange。
4. target token 文件权限为 `0600`。
